# 第 6 课：结业项目——我的 AI 学习知识库

你要把前面所有知识串成一个真实项目。重点不是内容多，而是工作过程清楚、可追踪、可协作。

## 6.1 最终成果


## 6.2 项目规则

- 不直接修改 `main`；
- 每个任务先创建 Issue；
- 每个 Issue 使用独立分支；
- 每个提交只做一件可说明的事；
- 每个 PR 写背景、改动、验证和风险；
- 合并前自审 Files changed；
- 不提交真实秘密、隐私或无授权内容；
- 合并后同步本地 `main` 并删除完成分支。

## 6.3 六个任务

### 任务 1：改造首页

创建 Issue：让第一次进入仓库的人在一分钟内知道这是什么、怎么使用。

分支：`docs/improve-homepage`

README 至少包含：项目目的、目录导航、更新方式、安全说明。

### 任务 2：添加一份可复用提示词

创建 Issue，明确提示词解决的问题和使用限制。

分支：`docs/add-analysis-prompt`

不要只贴提示词正文；还要说明输入、输出、使用示例和人工核验点。

### 任务 3：写 GitHub 核心概念笔记

分支：`docs/add-github-mental-model`

必须用自己的话解释：仓库、提交、分支、本地、远端、push、pull、PR、Issue。禁止照抄本教程。

### 任务 4：建立贡献指南

分支：`docs/add-contributing-guide`

在 `CONTRIBUTING.md` 中说明：如何提出学习资源、文件命名规则、禁止内容、PR 检查表。

### 任务 5：制造并解决一次冲突

1. 从同一个 `main` 创建 `experiment/title-a` 和 `experiment/title-b`；
2. 两个分支分别修改 README 同一个标题；
3. 先合并 A；
4. 再让 B 同步最新主线，观察冲突；
5. 人工决定最终标题，检查后完成合并。

只在练习仓库中做，不要在重要项目里第一次实验。

### 任务 6：运行一次 Actions

加入第 5 课的 `hello.yml`，手动运行。打开日志，写下：什么事件触发、运行在哪种环境、包含哪个步骤、结果是什么。

## 6.6 最终口试

不看教程，回答：

1. 你在本地保存文件后，为什么 GitHub 网站没变化？
2. 你已经 commit，为什么同伴仍看不到？
3. 已经 push，为什么 main 仍没变化？
4. PR 出现绿色检查，为什么仍需人审查？
5. 冲突为什么不能总让 AI 或 Git 自动选一边？
6. 一个 Token 被提交后，为什么删除文件不是第一解决方案？
7. AI 一次改了 40 个文件，你会如何缩小风险？

## 6.7 毕业宣言

当六个任务完成后，在学习日志最后写：

```markdown
## GitHub 入门结业

我真正获得的不是记住一串 Git 命令，
而是把变化组织成可追踪、可讨论、可验证、可安全接纳的协作能力。
```

这就是 GitHub 最值得理解的思想。
