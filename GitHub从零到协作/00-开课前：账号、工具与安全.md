# 第 0 课：账号、工具与安全

## 本课目标

完成后，你会拥有一个安全的 GitHub 账号，知道网页、GitHub Desktop、Git 命令行各自负责什么，并准备好贯穿全课的练习仓库。

## 0.1 注册账号

打开 [GitHub](https://github.com)，选择注册。用户名会出现在仓库网址、提交记录和公开主页里，建议：

- 简短、容易拼写；
- 尽量长期使用；
- 不包含身份证号、手机号等敏感信息；
- 用于求职时，最好不显得随意或冒犯。

邮箱用于验证身份和接收通知。注册后完成邮箱验证。

### 现在动手

登录后访问 `https://github.com/你的用户名`。能看到个人主页就算完成。

## 0.2 立刻开启双重验证

双重验证（2FA）相当于“密码之外再加一把钥匙”。在账号设置的 Password and authentication 中开启。优先使用验证器或通行密钥，并把恢复码存入可信的密码管理器或离线安全位置。

安全底线：

1. 不把恢复码截图后随手放在公开网盘；
2. 不把 Token、SSH 私钥、密码发给任何人或 AI；
3. 收到“仓库异常、请立即登录”的邮件时，从浏览器手动打开 GitHub，不直接点可疑链接；
4. 第三方应用只给完成任务所需的最小权限。

## 0.3 认识三种入口

### 浏览器：看项目与在线协作

适合创建仓库、阅读代码、编辑小文件、Issue、Pull Request、评审和设置。它最直观，因此我们先从这里学。

### GitHub Desktop：本地工作流的可视化驾驶舱

适合新手查看文件变化、创建分支、提交、同步和处理简单冲突。官方下载地址：[desktop.github.com](https://desktop.github.com/)。

### 命令行：可组合、可自动化的专业入口

Git 是底层工具，常用命令并不多。命令行不是“更高级的人才配用”，而是当你需要准确、批量或自动化时更方便。

三者不是三套互斥的系统。你完全可以用编辑器改文件、GitHub Desktop 提交、浏览器开 PR。

## 0.4 新手推荐路线

1. 浏览器跑通完整流程；
2. 安装 GitHub Desktop，理解本地与远端；
3. 只学 12 个常用 Git 命令；
4. 真实协作时再学冲突、回退和自动化。

## 0.5 公开仓库还是私有仓库

| 类型 | 谁能看到 | 适合 | 仍然不能放 |
|---|---|---|---|
| Public 公开 | 互联网上任何人 | 作品集、开源项目、公开笔记 | 密码、隐私、未授权资料 |
| Private 私有 | 你和获授权的人 | 私人练习、内部项目 | 密码、Token、密钥、违规数据 |

“私有”不是“保险箱”。成员可能误操作，账号可能被盗，仓库以后也可能改成公开。敏感凭证从一开始就不应进入 Git 历史。

## 0.6 两类身份不要混淆

- **网页登录**：密码、通行密钥或双重验证；
- **电脑连接 GitHub**：GitHub Desktop、GitHub CLI、HTTPS 凭证或 SSH 密钥。

GitHub 已不支持用账号密码直接进行 Git 命令行认证。命令行采用 HTTPS 时，通常用浏览器登录、凭证管理器或个人访问令牌；也可以使用 SSH。新手优先让 GitHub Desktop 或 GitHub CLI 帮你完成浏览器授权，不要手工把 Token 写进网址或文件。

## 0.7 课前检查表

- [ ] 已注册并验证邮箱；
- [ ] 已开启双重验证并保存恢复码；
- [ ] 能打开个人主页；
- [ ] 知道 Public 与 Private 的区别；
- [ ] 知道密码、Token、私钥和 `.env` 不得提交；
- [ ] 明白浏览器、Desktop、命令行可以混合使用。
