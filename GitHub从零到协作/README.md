# GitHub 从零到协作：给完全新手的实战课

> 你不需要会编程，也不需要先背命令。完成这套课程后，你会真正理解 Git、GitHub、仓库、提交、分支和 Pull Request 之间的关系，并能独立完成一次标准的 GitHub 协作流程。

## 这套课适合谁

- 从没用过 GitHub，看到英文界面和黑色终端就紧张的人；
- 会下载代码，却不知道 `clone`、`commit`、`push` 分别在做什么的人；
- 想管理自己的文章、提示词、课程或代码，而不仅是程序的人；
- 想参与开源项目，或与 AI 编程助手协作的人。

本课默认你有一台能上网的电脑。第一阶段只用浏览器；第二阶段推荐 GitHub Desktop；第三阶段才接触少量命令行。Windows、macOS 都能学。

## 先记住一句话

**Git 是“版本时间机器”，GitHub 是“把这台时间机器放到网上，并围绕它协作的工作平台”。**

Git 和 GitHub 不是一回事：Git 可以离线使用；GitHub 依赖网络，并提供账号、讨论、审查、自动化和开源社区。

## 最推荐的学习方法

每一课都按这个循环进行：

```text
先猜它为什么存在 → 看一个生活类比 → 亲手做一次
        ↑                              ↓
复述给别人听 ← 对照结果与排错 ← 故意改错一次
```

不要连续看完再动手。每读到“现在动手”，就真的操作。GitHub 是一种协作习惯，不是靠记忆掌握的知识。

建议建立一份 `学习日志.md`，每课写四行：

```markdown
## 第 X 课
- 我今天做成了：
- 我终于理解了：
- 我遇到的问题是：
- 下次我会先检查：
```

## 贯穿全课的项目

你会创建一个 `my-ai-learning` 仓库，用来管理自己的 AI 学习资料。它不要求会写代码，最终包含：

```text
my-ai-learning/
├── README.md          # 项目首页与使用说明
├── 学习日志.md         # 每次学习的提交记录
├── prompts/           # 提示词
├── notes/             # 笔记
├── resources/         # 资源索引，不放来路不明的大文件
├── CONTRIBUTING.md    # 如何参与
└── .gitignore         # 不应进入仓库的文件规则
```

## 学会的标准：不是背出多少命令

学完后，你应该能回答：

- 为什么提交应该小而清楚，而不是一天只交一次“大杂烩”？
- 为什么分支不是“复制一整个文件夹”？
- 为什么 Pull Request 叫“请求拉取”，却常被理解为“申请合并”？
- 为什么 `push` 之前常要先 `pull`？
- 为什么密码、Token、`.env` 不能提交，即使仓库是私有的？
- 为什么协作时应从 Issue 或任务开始，而不是直接修改 `main`？
- 为什么“合并成功”不等于“改动一定正确”？

如果你能解释这些问题，并独立完成“建仓库 → 建分支 → 修改 → 提交 → 推送 → PR → 审查 → 合并 → 同步”，就已经具备真实工作的基础。
